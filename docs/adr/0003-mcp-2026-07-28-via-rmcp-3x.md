# 3. MCP 2026-07-28 via rmcp 3.x

Date: 2026-08-14

## Status

Accepted

## Context

ShapePort exposes its data transformation capabilities to AI agents via the Model Context Protocol (MCP). The MCP specification has evolved significantly:

- **MCP 2024-11-05** — initial release, stdio only.
- **MCP 2025-03-26** — added Streamable HTTP, resource subscriptions, OAuth 2.1.
- **MCP 2026-07-28** — stateless Streamable HTTP (no server-sent events requirement), simplified session model, tighter security requirements.

The Rust ecosystem provides `rmcp` as the idiomatic MCP implementation library. `rmcp` 3.x tracks MCP 2026-07-28 and exposes:

- `transport-io` for stdio transport.
- `transport-streamable-http-server` for the stateless Streamable HTTP transport.
- Proc-macro tooling (`#[tool]`, `#[tool_router]`, `#[tool_handler]`) for ergonomic server definition.
- `schemars` integration for JSON Schema generation from Rust types.

Older rmcp 0.x and 1.x releases targeted earlier protocol revisions and have breaking API differences. Using the latest revision ensures compatibility with current AI agent runtimes (Cursor, Claude Desktop, etc.).

## Decision

ShapePort pins `rmcp = "3.1.2"` with `features = ["server", "macros", "transport-io", "transport-streamable-http-server"]` in `[workspace.dependencies]`. The MCP server in `crates/shapeport-mcp` implements the MCP 2026-07-28 specification.

The HTTP layer uses `rmcp` Streamable HTTP (`legacy_session_mode = false`) plus Axum Bearer middleware:

1. Bearer token authentication is required on non-loopback binds (`SHAPEPORT_MCP_TOKEN`).
2. Origin allowlist checking is delegated to `rmcp` (`with_allowed_origins`). A present Origin that does not match is rejected with 403; missing Origin is accepted so non-browser MCP clients work.

## Consequences

- ShapePort is compatible with MCP 2026-07-28 clients.
- The server does not maintain session state between requests (stateless Streamable HTTP).
- Upgrading to future MCP revisions will require updating the `rmcp` pin and potentially adjusting the middleware.
- stdio transport remains available for local / embedded use cases that do not require HTTP.
